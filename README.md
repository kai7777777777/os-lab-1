一、项目概述与选题背景
1.1 选题背景
操作系统（OS）作为计算机系统的核心软件，其内部机制（如进程调度、死锁检测、内存置换等）具有高度的抽象性、并发性和不可见性。传统的 OS 教学往往依赖于静态的图表或枯燥的命令行日志，学生难以直观地感知内核状态的微观变化，导致理论与实践脱节。
1.2 实验目标
本项目旨在开发一个基于 Web 的轻量级、交互式、可视化的操作系统仿真平台。通过动态动画和实时数据反馈，将抽象的算法逻辑具象化，帮助学生深入理解以下核心概念：
●	并发与并行: 直观感受多进程环境下的资源竞争。
●	同步与互斥: 理解信号量机制在解决临界区问题中的作用。
●	调度策略: 对比不同调度算法在不同场景下的性能差异。
●	智能化分析: 探索大语言模型 (LLM) 在辅助计算机系统教学中的潜力。

三、系统架构与设计
3.1 总体架构设计
系统采用 单页应用 (SPA) 架构，整体遵循 MVVM (Model-View-ViewModel) 设计模式的思想：
●	Model (数据层): 定义核心数据结构，如 PCB (进程控制块)、Memory Frame (页框)、Resource Matrix (资源矩阵)。

●	ViewModel (逻辑层): 通过 React Hooks (useState, useEffect, useReducer) 封装核心算法逻辑，驱动视图更新。

四、核心功能模块详解
4.1 进程与线程管理 (Process State Management)
功能描述: 实现经典的“五态模型”，展示进程生命周期。
算法逻辑:
●	PCB 结构: { id, name, state, arrivalTime, burstTime }
●	状态转换规则:
1.	New -> Ready: 进程创建后，提交 (Admit) 进入就绪队列。
2.	Ready -> Running: 调度器 (Dispatcher) 选中进程，分配 CPU。约束: 此时 CPU 必须空闲。
3.	Running -> Ready: 时间片耗尽 (Timeout) 或被高优先级抢占。
4.	Running -> Blocked: 进程请求 I/O 或等待事件。
5.	Running -> Terminated: 进程执行完毕 (Exit)。
6.	Blocked -> Ready: I/O 完成或事件发生 (Wakeup)。
可视化亮点: 使用不同颜色的卡片容器代表状态队列，操作按钮仅在符合逻辑状态下激活（如只有 Running 态进程才有 "Block" 按钮），防止非法操作。
4.2 进程通信与同步 (IPC & Synchronization)
功能描述: 解决经典的“生产者-消费者”问题，演示临界区保护。
核心机制 (信号量):
●	Mutex (互斥锁): 初始值 1。保护缓冲区操作的原子性。
●	Empty (空闲槽): 初始值 N。表示剩余可写入空间。
●	Full (已用槽): 初始值 0。表示当前可读取数据量。
操作伪代码:
// 生产者逻辑
function Producer() {
    wait(empty);  // P操作：申请空槽
    wait(mutex);  // P操作：申请互斥锁
    // --- 临界区开始 ---
    buffer.push(data); // 写入数据
    // --- 临界区结束 ---
    signal(mutex); // V操作：释放锁
    signal(full);  // V操作：增加已用计数
}

可视化亮点:
●	动态阻塞: 当缓冲区满时，点击“生产”会触发 UI 抖动警告，模拟进程阻塞 (Blocked)。
●	锁的可视化: 当 Mutex 被占用时，缓冲区上方显示红色锁图标，直观展示互斥状态。
4.3 CPU 调度算法 (CPU Scheduling)
功能描述: 对比不同调度策略的性能。
支持算法:
1.	FCFS (先来先服务):
○	原理: 简单的 FIFO 队列，按到达时间排序。
○	缺点: 容易产生“护航效应” (Convoy Effect)，当长作业在短作业前面时，短作业等待时间过长。
2.	SJF (短作业优先 - 非抢占):
○	原理: 每次从就绪队列选择 Burst Time (执行时间) 最小的进程。
○	优点: 理论上能获得最小的平均等待时间。
○	缺点: 可能导致长作业“饥饿” (Starvation)。
3.	RR (时间片轮转):
○	原理: 设置时间片 Quantum，轮流执行。未执行完的进程放回就绪队列末尾。
○	特点: 适用于分时系统，保证响应时间，防止进程长期独占 CPU。
可视化亮点: 自动生成甘特图 (Gantt Chart)，并实时计算平均等待时间 (AWT) 和 平均周转时间 (ATT)，便于量化对比。
五、创新扩展功能详解
5.1 AI 智能内核助手 (Gemini Powered)
设计初衷: 传统的仿真仅展示“结果”，缺乏“解释”。引入 LLM (大语言模型) 可以充当智能助教，帮助学生分析复杂的系统行为。
功能实现:
1.	内核日志分析: 系统实时记录进程状态变更日志，打包发送给 Gemini API，生成自然语言的分析报告（如“检测到进程频繁在 Ready/Running 切换，建议检查时间片设置...”）。
2.	调度策略顾问: 将当前进程列表（到达时间、突发时间）作为 Prompt 输入 AI，AI 分析数据分布特征，推荐最优算法（如“存在大量短任务 P3, P5，建议使用 SJF 以降低平均等待时间”）。
5.2 内存页面置换 (Page Replacement)
功能描述: 模拟虚拟内存管理中的缺页中断处理。
支持算法:
●	FIFO (先进先出): 淘汰在内存中驻留时间最久的页面。
●	LRU (最近最少使用): 淘汰最长时间未被访问的页面。
可视化: 动态展示页框 (Page Frame) 的填充过程，高亮显示 Hit (绿色) 与 Miss (红色)，自动计算缺页率和命中率。
5.3 银行家算法 (Deadlock Avoidance)
功能描述: 操作系统死锁避免的核心算法。
数据结构:
●	Available: 系统当前可用资源向量。
●	Max: 进程最大需求矩阵。
●	Allocation: 当前已分配矩阵。
●	Need: 需求矩阵 (Max - Allocation)。
核心逻辑: 当进程请求资源时，系统先进行“试探性分配”，然后运行安全性检测算法（寻找安全序列）。若系统进入不安全状态，则回滚操作并拒绝请求，弹出警告。

八、总结与展望
8.1 项目总结
本项目成功构建了一个功能完备、界面友好的操作系统原理可视化平台。
●	完备性: 覆盖了进程、内存、文件（磁盘）、死锁四大 OS 核心领域。
●	创新性: 创造性地引入 Generative AI 技术，将传统的“被动观察”转变为“主动交互与智能分析”，提升了实验教学的深度。
●	工程质量: 代码结构清晰，组件复用度高，算法逻辑严谨，具备较高的工程参考价值。
8.2 存在问题与改进方向
1.	多级反馈队列 (MLFQ): 目前调度算法尚未实现最复杂的 MLFQ，未来可增加此功能以模拟真实 OS 的调度策略。
2.	并发性能: 在模拟高频 IPC 操作时，前端动画渲染偶有掉帧，未来可引入 requestAnimationFrame 进行优化。
3.	真实内核对接: 目前所有演示均为前端模拟数据。未来可尝试通过 WebAssembly 技术，在浏览器中运行真实的轻量级 OS 内核（如 rCore），实现真正的内核可视化。
